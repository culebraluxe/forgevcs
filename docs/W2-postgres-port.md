# W2 — Porting the meta store to Postgres/Neon

**Status: PASS (2026-10-17).** `meta_store_suite` runs 20/20 cases against Neon on
`us-east-2`; the vendored CockroachDB build is unchanged in behaviour and still 15/15 on
its unit tests. Decision record: ADR-0001 §7.1 and its [outcome][outcome].

[outcome]: adr/0001-infrastructure-stack.md#71-outcome--w2-ported-and-proven-2026-10-17

## What the port is

One crate, two dialects. `scion-store-crdb` gains a `postgres` feature; nothing outside the
feature changes, so the upstream gate keeps testing the CockroachDB statements byte for byte.

| File | Change |
| --- | --- |
| `src/dialect.rs` (**new**) | `Dialect::{Cockroach, Postgres}`, `ACTIVE` selected by the feature. Owns the migration rewrite, the inline-cast rewrite, the retry budget, the session option, the follower-read clause, and the rustls root store |
| `src/migrations.rs` | `migrations()` returns the set adapted to `ACTIVE`; `MIGRATIONS` stays exported unchanged |
| `src/store.rs` | dialect-selected upsert/`UNNEST` constants; session option only for CockroachDB; `connect_raw` and TLS in `connect_fresh_for_tests` |
| `src/store/txn.rs` | `adapt_inline_sql` inside the three statement-preparation helpers; attempt budget from `Dialect::max_attempts` |
| `tests/neon_conformance.rs` (**new**) | the conformance suite against a configured Postgres/Neon URL |

SQL logic is untouched. What changed is four spellings and two behaviours:

| Divergence | CockroachDB | Postgres |
| --- | --- | --- |
| text columns | `STRING` | `TEXT` |
| byte columns | `BYTES` | `BYTEA` |
| audit sequence default | `DEFAULT unique_rowid()` | `GENERATED BY DEFAULT AS IDENTITY` |
| upserts (×3) | `UPSERT INTO …` | `INSERT … ON CONFLICT (…) DO UPDATE SET … = EXCLUDED.…` |
| `Consistency::Stale` | `AS OF SYSTEM TIME follower_read_timestamp()` | the strong statement (no follower reads exist) |
| startup option | `-c optimizer_use_forecasts=off` | omitted (Postgres rejects it) |
| retry budget | 10 attempts | 64 attempts (SSI aborts more often under contention) |

## Running it

Unpooled URL only. Neon's pooler runs transactions in transaction mode, which breaks
prepared statements and per-session `SERIALIZABLE`.

```sh
(cd upstream && SCION_TEST_CRDB_URL="$(grep '^DATABASE_URL_UNPOOLED=' ../.env.local \
  | cut -d= -f2- | tr -d '"')" \
  cargo test -p scion-store-crdb --features postgres --test neon_conformance -- --nocapture)
```

Without `SCION_TEST_CRDB_URL` the test prints `SKIP:` and passes, so the command is safe in
CI. Unit tests for both dialects need **no** database:

```sh
(cd upstream && cargo test -p scion-store-crdb --lib)
(cd upstream && cargo test -p scion-store-crdb --lib --features postgres)
```

## Isolation without `CREATE DATABASE`

`crdb_external` creates a throwaway database per case. Neon allows far fewer databases than
that per branch, so the Neon run keeps one database and gives each case its own
`repo_name`, which yields its own `repo_id`; every SPEC 5.2 table is keyed by `repo_id`
first, so cases cannot see each other. Rows accumulate across runs — the suite neither
minds nor cleans them.

## Findings that only running found

1. **The session option breaks every connection.** `optimizer_use_forecasts` is unknown to
   Postgres, and the failure happens during startup, so nothing works at all.
2. **Five more inline array casts.** Only two batched inserts were known; `objects`,
   `object_uploads`, `changeset_children`, `object_paths`, `landed`, and `redactions` also
   cast `::STRING[]`/`::BYTES[]`. Handled centrally in the prepare helpers.
3. **Ten retries are not enough for 32 writers.** `concurrent_redactions` failed with
   "retries exhausted after 10 attempts" under SSI; 64 attempts passed. This is the class of
   bug that would have appeared in production as an intermittent 503, not in a unit test.
4. **The harness assumed plaintext.** `connect_fresh_for_tests` used `NoTls`; Neon requires
   TLS on every connection.

## Explicitly not done

- `blob_store_suite` against the real bucket — W3, after this.
- A read-replica pool for stale reads: rejected in ADR §7.1 (correctness is unaffected;
  the benefit is latency, which is not the bottleneck at current volume).
- Vercel deployment of the migrated store: W4/deploy proof.
